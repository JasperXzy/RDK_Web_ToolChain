## 1. 文档目的

本文档定义 RDK WebToolChain 的产品目标、使用边界、核心流程、功能需求、非功能需求、阶段规划和验收标准。本文档是产品、前端、后端、工具链适配、测试和发布工作的共同依据。

具体组件、接口、数据结构和 Docker 调度方案见 [项目设计文档](./PROJECT_DESIGN.md)。

## 2. 产品背景

OpenExplorer 已提供完整的命令行模型转换能力，但实际落地仍存在较高使用门槛：

- 使用者需要理解 `march`、输入类型、Layout、Shape、Mean/Scale、校准方式和编译参数。
- 模型检查、校准数据预处理、量化编译、精度验证、性能验证散落在多个命令和脚本中。
- S100 和 S600 使用不同的目标架构、算子约束和编译能力，错误配置可能生成不可用结果。
- 编译过程时间较长，日志量大，失败后定位困难。
- ONNX、BC、HBM、CSV、JSON、HTML 等产物较多，缺少统一归档和结果解释。
- 板端验证涉及模型拷贝、运行环境、`hrt_model_exec` 参数和指标采集。

参考包中的 PTQ 流程包含浮点模型准备、模型检查、校准、量化编译、精度评估、性能评估及板端运行等阶段。RDK WebToolChain 的目标是将这些步骤组织成一条可理解、可恢复、可追溯的本地工作流。

## 3. 产品定位

RDK WebToolChain 是运行在开发者本机的模型转换工作台。用户通过浏览器完成模型导入、参数配置、任务执行、结果分析和产物导出；实际 OpenExplorer 命令在隔离的任务容器中执行。

产品不是：

- 面向公网的在线模型转换服务。
- 多租户云平台。
- 模型训练平台。
- 通用容器管理平台。
- 替代 OpenExplorer 的新编译器。

## 4. 产品愿景

让具备基础模型知识的开发者，在不了解大量工具链命令细节的前提下，也能安全、正确、可重复地将 ONNX 模型转换为适用于 S100/S600 的 HBM 模型，并清楚理解转换结果。

## 5. 产品目标

### 5.1 核心目标

1. 将模型转换主流程收敛为可视化向导。
2. 自动应用并校验 S100/S600 平台差异。
3. 隔离运行模型检查和量化编译任务。
4. 提供实时日志、阶段进度、取消、失败诊断和任务恢复。
5. 对转换产物、版本和配置进行完整归档。
6. 提供精度参考、静态性能和可选板端验证结果。
7. 保证模型和数据默认不离开本机。

### 5.2 非目标

首期不包含：

- 模型训练、数据标注和模型发布服务。
- 公网访问、账号注册、团队协作和权限审批。
- 自动修改不支持算子或自动重写模型结构。
- 任意用户 Python 代码的直接执行。
- QAT 训练流程。
- Caffe、TensorFlow、TFLite、PaddlePaddle 原生文件直接转换。
- 同时调度大量并发任务。
- Windows 原生和 macOS ARM 原生工具链运行。

## 6. 用户与使用场景

### 6.1 目标用户

#### 模型开发者

- 已获得训练完成的 ONNX 模型。
- 了解模型输入、预处理和业务精度指标。
- 希望快速判断模型能否部署到 S100/S600。

#### 嵌入式部署工程师

- 关注 HBM 输入输出、内存、latency、FPS 和 BPU 利用情况。
- 需要将模型部署到开发板进行验证。

#### 工具链维护者

- 负责维护 OpenExplorer 镜像、目标配置和解析规则。
- 需要定位不同工具链版本导致的行为差异。

同一位本地用户可以同时承担以上角色。首期不需要实现角色权限系统。

### 6.2 典型场景

1. 用户上传一个 ResNet/YOLO/分割 ONNX 模型，选择 S100 或 S600，完成 PTQ 转换并下载 HBM。
2. 用户先执行快速可行性检查，确认不支持算子及理论性能，再决定是否准备完整校准集。
3. 用户调整校准策略、输入预处理或编译参数，比较多次转换结果。
4. 用户将 HBM 上传到本机可访问的开发板，执行单帧推理和性能测试。
5. 用户导出某次任务的模型、配置、版本清单和报告，以便复现或提交问题。

## 7. 运行环境与前置条件

### 7.1 首期支持环境

- Ubuntu 22.04 x86_64。
- Docker Engine 和 Docker Compose。
- 浏览器：近期版本 Chrome 或 Edge。
- OpenExplorer 3.7.0 CPU 镜像。
- GPU 模式额外需要 NVIDIA Driver、NVIDIA Container Toolkit 和兼容 GPU。
- 板端验证额外需要可通过网络访问的 S100/S600 开发板。

### 7.2 本地运行约束

- Web 服务默认绑定 `127.0.0.1`。
- 不要求外部数据库、对象存储或消息队列。
- 模型、校准数据、日志和产物均保存在本机 Docker Volume。
- 工具链镜像已存在时，核心转换流程可离线运行。
- 参考包和工具链镜像的授权由使用者自行确认，产品不得默认上传或重新分发专有内容。

## 8. 产品原则

### 8.1 正确性优先

所有平台相关参数必须来自受控 Target Profile。系统不得依赖用户手工输入 `nash-e` 或 `nash-p` 来判断目标平台。

### 8.2 显式配置

多输入模型的输入顺序、Shape、类型和校准目录必须显式关联，不依赖文件遍历顺序或隐式字符串拼接。

### 8.3 任务不可变

任务提交后，其模型哈希、校准集、配置、目标平台和工具链版本形成不可变快照。修改参数必须创建新任务。

### 8.4 结果可解释

界面不仅显示“成功/失败”，还要解释算子部署位置、相似度、生成产物、性能结果和潜在风险。

### 8.5 本地可信但最小授权

产品允许控制宿主机 Docker，但用户不能通过 Web 参数获得任意容器、命令、镜像、挂载或网络控制能力。

## 11. 核心用户流程

### 11.1 首次启动

1. 用户执行 `docker compose up -d`。
2. 用户访问 `http://127.0.0.1:8080`。
3. 系统自动执行环境预检。
4. 如存在阻断项，首页展示原因及修复建议。
5. 环境可用后，用户创建项目或进入已有项目。

### 11.2 标准转换

1. 创建或选择项目。
2. 导入 ONNX 模型。
3. 系统解析模型输入输出、opset、IR 版本和动态维度。
4. 选择 S100 或 S600。
5. 配置训练输入、板端输入、Layout、Shape、Mean/Scale 等参数。
6. 上传 NPY 校准集，或上传图片并配置预处理流程。
7. 系统执行配置校验并生成 YAML 预览。
8. 提交模型检查和转换任务。
9. 页面展示实时阶段和日志。
10. 成功后展示 HBM、节点相似度、静态性能和完整产物。
11. 用户下载 HBM 或导出可复现任务包。

### 11.3 快速可行性评估

1. 导入 ONNX。
2. 选择目标平台并填写必要的动态 Shape。
3. 运行模型检查。
4. 可选运行 `fast-perf`。
5. 系统明确提示该结果不包含真实校准精度结论。

### 11.4 板端验证

1. 添加本地网络内的开发板。
2. 测试 SSH/SFTP 和 `hrt_model_exec` 可用性。
3. 从成功任务中选择 HBM。
4. 执行模型信息、单帧推理或性能测试。
5. 保存板卡、系统、运行参数、latency、FPS 和日志。

## 12. 功能需求

### 12.1 环境预检

#### ENV-001 Docker Engine 检查（P0）

系统必须检查：

- Docker Socket 是否可访问。
- Docker Engine API 是否响应。
- 宿主机架构是否为 `linux/amd64`。
- Docker 数据盘剩余空间是否达到用户配置的最低阈值。

#### ENV-002 工具链镜像检查（P0）

系统必须检查已配置的 CPU/GPU Runner 镜像是否存在，并显示：

- 镜像名称和 tag。
- 镜像 ID/digest。
- Runner 合约版本。
- OpenExplorer、HMCT、HBDK、HBRT 版本探测结果。

镜像不存在时，系统只能给出加载/构建指导，不能静默从公网拉取。

#### ENV-003 GPU 检查（P1）

用户启用 GPU 模式时，系统应检查：

- NVIDIA Runtime 是否可用。
- GPU 数量和设备 ID。
- 驱动信息。
- Runner 镜像是否能够成功执行 GPU Smoke Test。

GPU 不可用不得阻止 CPU 转换。

#### ENV-004 数据卷检查（P0）

系统必须验证状态卷和任务卷可写，并能够创建、读取、删除临时测试文件。

### 12.2 项目管理

#### PROJ-001 创建项目（P0）

用户可填写项目名称和备注。名称可重复，但项目 ID 必须唯一。

#### PROJ-002 项目总览（P0）

项目详情展示：

- 模型数量。
- 校准集数量。
- 任务数量及状态分布。
- 最近成功产物。
- 项目磁盘占用。

#### PROJ-003 删除项目（P0）

删除前必须展示将被删除的模型、校准集、任务和产物数量，并要求二次确认。运行中的项目不能直接删除。

#### PROJ-004 项目导入导出（P1）

用户可导出项目元数据、配置和选定产物。导出包不得默认包含板端凭据。

### 12.3 模型导入与解析

#### MODEL-001 上传 ONNX（P0）

- 支持从浏览器选择本地 `.onnx` 文件。
- 上传期间展示进度。
- 系统计算 SHA-256，并可对同一项目内的完全相同文件复用存储。
- 原始文件名只用于展示，内部路径使用系统生成 ID。

#### MODEL-002 模型合法性初检（P0）

系统必须检查：

- 扩展名和基本文件签名。
- ONNX 能否解析。
- IR version。
- opset version。
- 输入输出节点。
- 静态/动态维度。
- 是否存在 external data 依赖。

首期支持范围为 IR version ≤ 9、opset 10～19。超出范围时标记为阻断错误。

#### MODEL-003 模型信息展示（P0）

展示：

- 文件大小、哈希、上传时间。
- IR/opset。
- 输入输出名称、Shape、dtype。
- 算子类型及数量。
- 动态维度提示。

#### MODEL-004 模型 Smoke Test（P1）

用户提供一份合法输入后，系统可使用 HBRuntime 对浮点模型执行单次推理，记录输入输出信息和执行结果。

#### MODEL-005 模型版本（P1）

同一逻辑模型可关联多个 ONNX 版本，每个版本拥有独立哈希和转换历史。

### 12.4 目标平台

#### TARGET-001 S100 Profile（P0）

系统内置且不可由普通表单绕过以下约束：

- `march = nash-e`。
- `core_num = 1`。
- `max_l2m_size = 0`。
- 使用 S100/S100P 对应的算子支持与约束资料。

#### TARGET-002 S600 Profile（P0）

系统内置：

- `march = nash-p`。
- `core_num = 1` 或 `2`。
- `max_l2m_size` 支持关闭、自动或平台允许范围内的数值。
- 使用 S600 对应的算子支持与约束资料。

#### TARGET-003 Profile 版本快照（P0）

任务必须保存 Profile ID、版本和完整能力快照，避免后续升级 Profile 后无法复现历史任务。

### 12.5 输入配置

#### INPUT-001 输入节点列表（P0）

系统根据 ONNX 自动生成输入节点表单。P0 支持单个静态输入；数据结构必须按输入列表设计，为 P1 多输入预留能力。

#### INPUT-002 训练输入配置（P0）

支持：

- `input_type_train`：rgb、bgr、gray、yuv444、featuremap。
- `input_layout_train`：NCHW、NHWC。
- `input_shape`。
- Mean、Scale、Std。

#### INPUT-003 Runtime 输入配置（P0）

支持：

- nv12、rgb、bgr、yuv444、gray、featuremap。
- input source：ddr、pyramid、resizer，按版本和场景逐步开放。
- input batch。

#### INPUT-004 交叉字段校验（P0）

至少包含：

- 动态输入必须填写目标 Shape。
- NV12 图像尺寸不得包含奇数宽高。
- Mean/Scale 数量必须与通道配置一致。
- 多输入参数顺序必须与输入节点显式关联。
- featuremap 非四维输入时禁止无效图像归一化配置。
- S100 禁止设置多 Core 或 L2M。

### 12.6 校准集与预处理

#### CAL-001 NPY 校准集（P0）

- 支持多文件上传和压缩包导入。
- 每个样本独立保存。
- 检查 dtype、Shape 和文件可读性。
- 推荐 20～100 个代表性样本。
- 样本过少或分布异常时显示警告，但是否阻断由配置决定。

#### CAL-002 图片校准集（P0）

支持 JPEG、PNG、BMP 等常见图片格式。图片必须通过预处理 Recipe 转换为 NPY 后才能作为标准校准输入。

#### CAL-003 声明式预处理（P0）

支持按顺序组合：

- 图片读取方式。
- Resize、等比例 Resize。
- Center Crop。
- Letterbox/Padding。
- RGB/BGR/Gray 转换。
- HWC/CHW 转换。
- dtype 转换。
- Mean、Scale、Std 归一化。

P0 不允许在 Web 界面直接上传和执行任意 Python 脚本。

#### CAL-004 预处理预览（P0）

用户提交转换前，系统至少展示一份样本的：

- 原图。
- 处理后可视化结果（适用时）。
- Shape、dtype、最小值、最大值、均值。
- 预期模型输入信息。

#### CAL-005 校准集版本（P0）

校准集由源文件清单、每个文件哈希、Recipe 版本和生成结果清单共同标识。任何源文件或 Recipe 变化都生成新版本。

### 12.7 配置生成

#### CFG-001 规范化配置（P0）

系统以类型化 JSON 作为配置事实来源，并根据工具链适配器生成 YAML。

#### CFG-002 YAML 预览（P0）

提交前展示最终 YAML，并标识：

- 系统锁定字段。
- 用户配置字段。
- 默认字段。
- 警告字段。

#### CFG-003 高级配置（P1）

逐步开放：

- calibration/quant config。
- compile mode。
- optimize level。
- balance factor。
- cache。
- jobs。
- max time per function call。

高级配置仍需经过白名单和跨字段校验。

#### CFG-004 配置模板（P1）

支持分类、检测和分割等模板。模板只提供初始值，不得替代用户确认模型真实预处理。

### 12.8 模型检查

#### CHECK-001 可转换性检查（P0）

系统使用目标 Profile 调用 `hb_compile --model ... --march ...`，并记录：

- 完整参数数组。
- 开始/结束时间。
- 退出码。
- stdout/stderr。
- 工具版本。

#### CHECK-002 检查结果（P0）

结果页应区分：

- 模型合法性错误。
- 不支持算子。
- 算子约束不满足。
- 动态 Shape 缺失。
- 工具链内部错误。
- 环境/资源错误。

#### CHECK-003 算子部署信息（P1）

在工具输出允许时，展示算子运行于 BPU、CPU 或未知设备的情况，并关联 S100/S600 算子资料。

### 12.9 模型转换任务

#### RUN-001 提交任务（P0）

提交前必须冻结以下快照：

- 模型 ID、文件哈希。
- 校准集 ID 和清单哈希。
- 规范化配置和生成 YAML。
- Target Profile。
- Runner 镜像名称和 digest。
- 应用、Runner 和工具链版本。

#### RUN-002 隔离任务容器（P0）

每次转换使用独立任务容器。任务容器必须：

- 使用系统允许的 Runner 镜像。
- 使用系统生成的容器名和 Label。
- 只挂载任务数据卷。
- 不使用 `privileged`。
- 默认不启用宿主机网络。
- 设置资源和超时限制。

#### RUN-003 任务阶段（P0）

界面展示：

```text
QUEUED
→ PROVISIONING
→ INSPECTING
→ CHECKING
→ PREPROCESSING
→ COMPILING
→ VERIFYING
→ COLLECTING
→ SUCCEEDED / FAILED / CANCELLED / INTERRUPTED
```

未启用的步骤显示为 `SKIPPED`。

#### RUN-004 实时日志（P0）

- 日志延迟目标小于 1 秒。
- 支持自动滚动、暂停滚动、文本搜索和下载。
- stdout/stderr 在显示上可区分。
- 页面刷新或短暂断线后可续接。

#### RUN-005 取消任务（P0）

用户可取消排队或运行任务。运行任务先发送停止请求，超过宽限时间后强制终止。取消后仍保存已产生的日志和可识别产物。

#### RUN-006 重试（P0）

- 环境类失败可按相同快照创建新 Attempt。
- 修改配置后必须创建新 Run。
- 系统不得覆盖历史 Attempt 的日志和结果。

#### RUN-007 重启恢复（P0）

控制容器重启后必须根据 SQLite 状态和 Docker Label 恢复或标记运行任务，不得将未知任务错误标记为成功。

#### RUN-008 并发控制（P0）

默认最多一个活跃转换任务，其余任务排队。P1 可配置 CPU/GPU 各自并发数。

### 12.10 结果与产物

#### RESULT-001 成功判定（P0）

任务成功必须同时满足：

- Runner 正常结束。
- `hb_compile` 退出码为 0。
- 最终 HBM 存在且非空。
- 必需日志与配置快照存在。
- 产物清单成功生成。

日志中出现某个“SUCCESS”字符串不能单独作为成功依据。

#### RESULT-002 产物清单（P0）

系统识别并分类：

- 原始/优化/校准/PTQ ONNX。
- quantized BC。
- HBM。
- node info CSV。
- quant info/advice JSON。
- 静态性能 HTML/JSON。
- `hb_compile.log`。
- 生成的 YAML。
- `request.json`、`result.json` 和版本清单。

#### RESULT-003 结果摘要（P0）

至少展示：

- 目标平台。
- HBM 文件名和大小。
- 工具链版本。
- 总耗时和各阶段耗时。
- 输出节点 Quantized Cosine。
- 最低节点 Cosine 及节点名。
- 静态 FPS/latency（存在时）。
- 内存估计（存在时）。
- 警告和建议数量。

#### RESULT-004 节点分析（P1）

支持按节点名称、类型、设备和 Cosine 筛选。低相似度节点应突出显示，但必须说明 Cosine 不等同于最终业务精度。

#### RESULT-005 报告查看（P0）

HTML 报告在受限 iframe 中展示；不允许报告脚本访问父页面、Docker API 或本地设置。

#### RESULT-006 下载和导出（P0）

支持：

- 单个产物下载。
- HBM 快速导出。
- 完整可复现任务包导出。

### 12.11 精度与一致性验证

#### VERIFY-001 单样本推理（P1）

用户可为 ONNX/BC 选择测试输入，查看输出 Shape、dtype、统计信息和可下载结果。

#### VERIFY-002 模型阶段比较（P1）

支持使用 `hb_verifier` 比较兼容的 ONNX、BC、HBM 组合，展示：

- Cosine Similarity。
- Consistency。
- Mismatched Elements。
- Max Abs Diff。
- Max Rel Diff。

#### VERIFY-003 业务精度评测接口（P2）

允许由受控插件提供分类、检测或分割评测逻辑。插件必须由本地管理员安装，不能通过普通任务参数提交任意代码。

### 12.12 任务比较

#### COMPARE-001 多任务比较（P1）

用户可选择同一模型的 2～4 个成功任务进行比较：

- S100/S600。
- 校准集和 Recipe。
- 校准算法。
- 编译参数。
- HBM 大小。
- Cosine。
- 静态/板端性能。

#### COMPARE-002 配置差异（P1）

以结构化字段展示差异，避免只做 YAML 文本 Diff。

### 12.13 开发板管理与验证

#### BOARD-001 添加设备（P1）

设备信息包含：名称、平台、IP/主机名、SSH 端口、用户名和认证方式。凭据只保存在本机状态卷，不进入任务导出包和普通日志。

#### BOARD-002 连接预检（P1）

检查：

- 网络连通性。
- SSH/SFTP。
- 板卡平台。
- 系统和运行库版本。
- 可用磁盘空间。
- `hrt_model_exec` 路径和版本。

#### BOARD-003 模型信息（P1）

调用 `hrt_model_exec model_info` 并展示模型输入输出信息。

#### BOARD-004 单帧推理（P1）

支持上传或选择输入文件，调用 `hrt_model_exec infer`，保存推理时间、输出文件和日志。

#### BOARD-005 性能测试（P1）

支持配置：

- frame count 或 perf time。
- thread num。
- core ID。
- profile path。

结果至少包含平均、最小、最大 latency 和 FPS。

### 12.14 设置与维护

#### SET-001 镜像设置（P0）

允许配置经过管理员确认的 CPU/GPU Runner 镜像。镜像名称必须进入本地允许列表后才能用于任务。

#### SET-002 资源设置（P0）

支持配置默认任务超时、CPU、内存、共享内存、并发数和最低剩余磁盘空间。

#### SET-003 存储管理（P0）

展示各项目、任务和产物磁盘占用。清理必须由用户明确触发，不自动删除成功 HBM。

#### SET-004 本地备份恢复（P1）

支持导出和恢复 SQLite、项目元数据及选定任务数据。恢复前验证 schema 和文件清单。

#### SET-005 无遥测（P0）

产品不得默认向外部发送模型、文件名、日志、指标或使用统计。若未来增加更新检查，必须显式可关闭并与业务数据完全隔离。

## 13. 状态与错误呈现

### 13.1 错误等级

| 等级 | 含义 | 示例 |
|---|---|---|
| Blocker | 无法继续 | Docker 不可用、模型无法解析、平台参数非法 |
| Error | 当前任务失败 | `hb_compile` 非零退出、OOM、产物缺失 |
| Warning | 可继续但存在风险 | 校准样本过少、伪校准、Cosine 较低 |
| Info | 普通信息 | 使用的镜像、工具版本、默认参数 |

### 13.2 错误信息要求

错误必须包含：

- 用户可理解的摘要。
- 所属阶段。
- 机器可识别错误码。
- 原始日志位置。
- 可能原因。
- 可执行的下一步建议。

系统不得将完整 Python Traceback 作为唯一用户错误信息。

## 14. 非功能需求

### 14.1 安全

#### NFR-SEC-001 本地访问

默认仅监听 `127.0.0.1`。切换到局域网监听必须是高级配置，并展示 Docker 控制权限风险。

#### NFR-SEC-002 Docker 参数白名单

前端请求不能直接控制：

- 镜像名。
- entrypoint/command。
- bind mount 源路径。
- `privileged`。
- host PID/network/device。
- Docker API 任意资源 ID。

#### NFR-SEC-003 路径安全

所有任务文件路径必须是系统生成的相对路径，并在访问前完成规范化和根目录边界检查。

#### NFR-SEC-004 本地请求保护

使用随机本地会话密钥、SameSite Cookie、Origin/Host 检查和 CSRF 保护，降低恶意网站请求 localhost API 的风险。

#### NFR-SEC-005 凭据保护

板端密码或私钥不得写入普通日志、任务参数、Docker Label 或可导出 Manifest。

### 14.2 可靠性

#### NFR-REL-001 持久化队列

排队任务和运行快照写入 SQLite 后才算提交成功。

#### NFR-REL-002 崩溃恢复

控制容器异常重启后能够重建任务状态，不丢失已完成产物。

#### NFR-REL-003 幂等收集

日志和产物收集可重复执行，不产生重复记录或覆盖历史 Attempt。

#### NFR-REL-004 精确清理

系统只能删除带有本产品 Label 且 ID 与数据库记录一致的容器，不得执行全局 prune。

### 14.3 性能

#### NFR-PERF-001 UI 响应

除上传和工具链任务外，普通本地 API 的 P95 响应时间目标小于 300ms。

#### NFR-PERF-002 日志

正常情况下，容器日志到页面的可见延迟目标小于 1 秒。

#### NFR-PERF-003 大文件

上传和下载采用流式处理，不将完整模型或产物加载到后端内存。

#### NFR-PERF-004 并发

P0 默认单任务执行，确保模型转换不会因无控制并发耗尽主机内存。

### 14.4 可用性

#### NFR-UX-001 向导保存

未提交的转换草稿自动保存，刷新页面后可恢复。

#### NFR-UX-002 默认值解释

每个工具链参数显示用途、默认值、目标平台限制和风险提示。

#### NFR-UX-003 高级参数隔离

普通模式仅显示完成转换所需参数，高级参数折叠展示。

### 14.5 可维护性

#### NFR-MAINT-001 适配器隔离

OpenExplorer 版本相关命令、配置生成和输出解析必须位于版本化适配器中。

#### NFR-MAINT-002 合约版本

控制器与 Runner 使用显式版本化 `request.json`/`result.json` 合约。

#### NFR-MAINT-003 数据迁移

SQLite schema 变更必须通过迁移脚本完成，启动时不得静默丢弃未知字段。

### 14.6 隐私与离线

- 核心工作流在工具链镜像和依赖已就绪时可完全离线。
- 不调用外部模型分析 API。
- 不上传日志到第三方错误跟踪服务。
- 所有导出操作由用户显式触发。

## 15. 产品成功指标

首个可用版本达到以下指标即可视为成功：

1. 用户可通过 Web 完成官方 ResNet18 示例的 S100 转换。
2. 同一模型切换 S600 后，系统自动生成 `nash-p` 及合法 S600 参数。
3. 任意任务都能导出模型、校准清单、YAML、版本 Manifest、日志和 HBM。
4. WebToolChain 重启后，已完成任务和排队任务仍可见。
5. 运行任务可取消，且不会残留无归属容器。
6. 模型、校准数据和日志在默认配置下不产生外部网络传输。
7. 所有 Docker 任务只使用允许列表中的镜像和固定 Runner entrypoint。

## 16. P0 验收场景

### AC-001 首次环境预检

**给定** Docker Engine 正常、CPU Runner 镜像存在，  
**当** 用户首次打开页面，  
**则** 系统显示环境可用，并列出 Docker、镜像、存储和版本信息。

### AC-002 S100 标准转换

**给定** 合法 ONNX、正确输入配置和 20～100 份校准样本，  
**当** 用户选择 S100 并提交转换，  
**则** 最终 YAML 使用 `nash-e`、`core_num=1`、L2M 关闭，并生成有效 HBM 和产物清单。

### AC-003 S600 标准转换

**给定** 同一模型和校准集，  
**当** 用户选择 S600 和双 Core，  
**则** 最终 YAML 使用 `nash-p`、`core_num=2`，并拒绝超出平台范围的 L2M 配置。

### AC-004 配置阻断

**给定** Runtime 输入为 NV12 且宽或高为奇数，  
**当** 用户尝试提交，  
**则** 系统在创建任务容器之前阻止提交并指出具体输入节点和维度。

### AC-005 任务失败

**给定** `hb_compile` 返回非零退出码，  
**当** 任务结束，  
**则** 状态为 FAILED，保留日志和已有产物，并展示阶段、错误码和建议；不得生成成功标记。

### AC-006 任务取消

**给定** 一个正在编译的任务，  
**当** 用户点击取消并确认，  
**则** 容器被停止，任务状态为 CANCELLED，日志可下载，容器随后被精确删除。

### AC-007 控制器重启

**给定** 一个运行中的任务容器，  
**当** WebToolChain 控制容器重启，  
**则** 系统通过 Label 找到任务容器并恢复监控，或在无法恢复时标记为 INTERRUPTED，而不是丢失任务。

### AC-008 Docker 参数保护

**给定** 一个伪造 API 请求，尝试传入任意镜像、宿主机挂载路径或 `privileged=true`，  
**当** 后端校验请求，  
**则** 请求被拒绝，且不会调用 Docker Engine 创建容器。

## 17. 分阶段交付

### 阶段 M0：技术闭环

- 固化 Runner 合约。
- 固化 S100/S600 Profile。
- 使用 API 或最小页面完成 ResNet18 检查、转换和产物收集。
- 验证控制器容器调用宿主机 Docker。

### 阶段 M1：P0 产品闭环

- 环境预检。
- 项目、模型和校准集管理。
- 转换向导。
- 实时日志、取消和恢复。
- 结果摘要、产物和导出。
- 安全白名单和本地请求保护。

### 阶段 M2：质量与比较

- HBRuntime 和 `hb_verifier`。
- 多输入、动态 Shape。
- 高级量化配置。
- 多任务比较。
- GPU Worker。

### 阶段 M3：板端闭环

- 设备管理。
- `model_info`、`infer`、`perf`。
- 板端结果与转换任务关联。

### 阶段 M4：扩展能力

- 精度 Debug。
- 受控评测插件。
- QAT。
- 新 OpenExplorer 版本适配。

## 18. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Docker Socket 等价于高权限控制 | 宿主机安全 | 本地监听、参数白名单、固定镜像与 entrypoint、无任意挂载 |
| 工具链输出随版本变化 | 报告解析失败 | 版本化 Adapter、优先读取 CSV/JSON、保留原始日志 |
| 校准预处理与训练不一致 | 精度下降 | Recipe 显式化、样本预览、统计检查、警告说明 |
| 参考示例默认 `nash-e` | S600 配置错误 | Target Profile 强制生成 `march` 与能力约束 |
| 大模型和中间产物占用磁盘 | 主机空间不足 | 预检、用量展示、任务级清理、导出后可删除中间件 |
| 编译任务耗尽内存 | 主机卡顿或 OOM | 默认单并发、资源限制、最低可用资源检查 |
| 控制器重启导致状态不一致 | 任务丢失 | SQLite 持久化、Docker Label、启动 reconciliation |
| 工具链授权限制 | 无法分发 | Controller 与专有 Runner 分离，本地构建/加载 Runner |

## 19. 待确认事项

以下事项不阻塞 M0，但应在进入对应阶段前确认：

1. 首个发行版是否只支持 Ubuntu 22.04，还是同时覆盖其他 Linux 发行版。
2. P0 是否必须支持多输入模型。
3. CPU/GPU Runner 镜像由项目本地构建，还是仅引用用户已加载的官方镜像。
4. 是否需要默认内置分类/检测/分割预处理模板。
5. 板端认证优先使用 SSH Key 还是兼容密码认证。
6. 完整导出包是否默认包含所有中间 ONNX/BC，或只包含可复现所需最小集合。

## 20. 术语

| 术语 | 含义 |
|---|---|
| PTQ | Post-training Quantization，训练后量化 |
| QAT | Quantization-aware Training，量化感知训练 |
| HBM | 可在目标平台部署的编译模型 |
| HBIR/BC | 工具链中间表示及对应文件 |
| Target Profile | 描述 S100/S600 能力与限制的版本化配置 |
| Runner | 运行在 OpenExplorer 容器中的固定任务执行程序 |
| Controller | 提供 Web/API、任务调度和 Docker 管理的本地控制容器 |
| Run | 一次不可变的模型转换请求 |
| Attempt | 同一个 Run 快照的一次实际执行尝试 |
| DooD | Docker-outside-of-Docker，容器调用宿主机 Docker Engine |
